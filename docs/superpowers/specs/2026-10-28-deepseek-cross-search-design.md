# 流程助手：DeepSeek 跨模块搜索设计

日期：2026-10-28

## 目标

在现有 Chrome 插件「流程助手」上增加：

1. 助手窗口内跨 **流程 / 菜单 / 待办** 搜索  
2. 用 **DeepSeek** 理解用户说法并决策；架构预留切换其他 OpenAI 兼容模型  
3. 决策为「唯一高置信」时直接打开；多条或不确定时在助手窗口列出  
4. **流程与菜单（及待办）严格区分**：不混在同一无分组列表里；用户明确说「打开某流程」时只走流程通道  

不把 API Key 写进仓库，不发到聊天；Key 只存在用户本机 `chrome.storage.local`。

## 方案

采用「本地先搜，模型只做理解和排序」：

1. 插件先判断用户意图范围（见下节），再只收集该范围的候选  
2. 把用户原话 + 该范围精简候选发给 DeepSeek  
3. 模型返回结构化 JSON  
4. 插件执行：直接打开，或**按类型分组**列出  

无 Key 或请求失败时：退回现有「仅流程名规则匹配」逻辑，不阻断打开请假等已有能力。

## 意图范围：流程与菜单分开

插件在调模型之前用规则识别意图（不依赖模型）：

| 用户说法特征 | 意图 `scope` | 候选只含 |
|---|---|---|
| 含「流程」，或「打开/发起/新建」+ 像流程名的对象（如「打开请假」「发起内部留言」） | `workflow` | 仅流程 |
| 含「菜单」「进入」「打开某某模块/页面」，且未提流程 | `menu` | 仅菜单 |
| 含「待办」「我的待办」「待我审批」等 | `todo` | 仅待办 |
| 含糊（如「请假」「找一下考勤」） | `all` | 三类都收集，但展示仍分组 |

补充规则：

1. **明确打开流程**：`scope=workflow`。本地对流程名能唯一命中（含「请假」对上「请假申请」这类）→ **直接打开**，可以不调模型。命中 0 条 → 提示流程列表中无此名称。命中多条 → 只列出**流程**候选项，不夹菜单。  
2. **`scope=all` 且模型返回多条**：助手窗口必须分三块展示，标题分别为「流程」「菜单」「待办」；每一块内部才是列表。禁止把菜单项和流程名排在同一个扁平列表里。  
3. **`decision=open`**：只能打开与当前 `scope` 一致的类型；若 `scope=workflow` 却返回 menu，插件忽略并改为只在流程结果里处理。  
4. 模型 Prompt 中写明：候选已按类型分开；`scope=workflow` 时禁止推荐菜单。

## 选项页与多模型预留

新增 `options.html` / `options.js`，在 `manifest.json` 注册 `options_ui`。

字段：

| 字段 | 说明 |
|---|---|
| `provider` | 当前先固定可选 `deepseek`；结构上允许以后加 `openai` 等 |
| `apiKey` | 密钥，仅存 `chrome.storage.local` |
| `baseUrl` | 默认 `https://api.deepseek.com` |
| `model` | 默认 `deepseek-chat` |
| `enabled` | 是否启用 AI 搜索；关闭则只用本地规则 |

调用统一走 OpenAI 兼容接口：

`POST {baseUrl}/v1/chat/completions`

请求头：`Authorization: Bearer {apiKey}`。  
这样以后加其他兼容服务，主要是改 `provider` 默认值与说明，不必重写内容脚本。

助手面板增加「设置」入口，打开选项页。不在对话或日志里打印完整 Key。

## 本地候选怎么来

均在用户当前已登录的平台页面上收集，不另开无登录态。

### 流程

沿用现有逻辑：进入流程定义页，从表格读取名称、代码、主视图、是否禁用。只把未禁用项交给模型。

### 菜单

从当前页可见的导航 DOM 收集（顶栏 `menuitem`、侧栏链接等），得到：

- `title`：可见文案  
- `path`：能读到的路由或 `href`（没有则空）  
- `selectorHint`：便于再次点击的短描述（如文案本身）  

去重后限制数量（例如最多 80 条），避免 Prompt 过大。

### 待办

优先：若当前已在「我的待办」且表格有数据，直接读行（标题、单号、类型等能读到的列）。  
否则：候选里放一条「入口」类结果，指向待办菜单；或短暂切到待办页读取后再切回（实现时以少打断用户为准；第一期可先支持「当前已在待办页则搜索待办行，否则只返回待办入口」）。

每条候选统一为：

```json
{
  "type": "workflow" | "menu" | "todo",
  "id": "稳定短 id",
  "title": "显示名",
  "subtitle": "代码/路径/补充",
  "openable": true
}
```

## DeepSeek 输入与输出

### 系统说明（要点）

你是目标信息平台助手。根据用户话从候选中选择。只能使用给定候选。  
候选带 `type`（workflow / menu / todo），不要把不同类型当成同一类。  
若请求中 `scope` 为 `workflow`：只能选 workflow；只有一条高置信则 `decision=open`。  
若只有一条高置信且可打开：`decision=open`。  
若同类型下多条都合理或拿不准：`decision=choose`，`candidates` 最多 8 条且尽量同一 `type`。  
若没有合适的：`decision=none`。  
只输出 JSON，不要 Markdown。

### 用户消息

包含：用户原话；`scope`；候选数组（type/id/title/subtitle），可按类型分段标注。

### 模型 JSON

```json
{
  "decision": "open" | "choose" | "none",
  "type": "workflow" | "menu" | "todo" | null,
  "id": "string|null",
  "title": "string|null",
  "reason": "一句中文原因",
  "candidates": [{ "type": "...", "id": "...", "title": "..." }]
}
```

解析失败或字段非法：视为 AI 失败，退回本地流程规则匹配。

## 执行规则

| decision | 行为 |
|---|---|
| `open` + workflow | 走现有打开流程逻辑（点「新建流程」/路由重置），成功后清掉 URL 中 `code` |
| `open` + menu | 按文案点击对应菜单项；点不到则提示并改为列出 |
| `open` + todo | 点击对应待办行或打开入口；点不到则列出 |
| `choose` | 助手窗口**按「流程 / 菜单 / 待办」分块**列出，点击某条再执行打开 |
| `none` | 提示未找到；若当时是流程意图，只提示流程相关名称 |

「能确定就直接打开」：

- **流程意图 + 本地唯一命中**：插件直接打开，不强制经过模型  
- 其余情况：模型判定；插件侧额外保护：  
  - `open` 的 id 必须落在本次候选里，否则改 `choose` 或 `none`  
  - `open` 的 type 必须符合当前 `scope`（`workflow` 意图不得打开菜单）  
  - 流程禁用项不得打开  

## 权限与安全

- `manifest` 增加 `storage`；若 DeepSeek 请求由扩展后台发出，增加 `host_permissions` 含 `https://api.deepseek.com/*`（自定义 Base URL 时，说明用户需在扩展中允许对应域名，第一期可只放行官方域名 + 可选用户填写的主机）。  
- 推荐由 **service worker / background** 发模型请求，避免在页面环境暴露 Key。内容脚本只传用户话与候选，收回 JSON。  
- 不把 Key、完整候选大包写入远程日志。

## 与现有行为的关系

保留：拖拽、默认收起、刷新清 `code`、二次打开流程。  
增强：有 Key 且启用 AI 时，含糊说法走跨模块搜索但结果分组；明确「打开某某流程」只走流程通道，唯一命中则直接打开。

## 完成标准

1. 选项页可保存 DeepSeek Key，助手可切换启用 AI。  
2. 说「打开请假流程」且仅一条流程匹配时，直接打开发起弹窗，助手结果中不夹菜单项。  
3. 流程多名命中时，只列出流程；菜单与流程分块显示，不混排。  
4. 说含糊需求（如「我想请假」）时，有 Key 能直接打开或分组列出。  
5. 说菜单类（如「打开待办」）能进待办或只列菜单/待办候选。  
6. 无 Key 时仍能用原规则打开流程。  
7. 仓库与聊天中不出现真实 Key。
