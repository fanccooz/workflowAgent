# 华荣流程发起技能设计

日期：2026-10-28

## 目标

做一个个人 Cursor 技能。用户在已登录的华荣照明信息平台里，用自然语言说要发起哪条流程时，技能从当前页面直接打开发起弹窗，用来填写一张单据。

站点前缀：

`https://test.warom-lighting.com/v2_debug_ouyang/#/`

流程定义页：

`https://test.warom-lighting.com/v2_debug_ouyang/#/workflow/workflow-base/agent`

该页在地址上带有流程代码时，会按代码打开发起弹窗。例如代码为 `00003` 时，地址是：

`https://test.warom-lighting.com/v2_debug_ouyang/#/workflow/workflow-base/agent?code=00003`

页面用去掉前导零后的代码比较，因此 `00003`、`003`、`3` 指向同一条定义。弹窗用于新建单据，不打开流程定义编辑页。

## 技能位置与触发

技能目录：`C:\Users\1\.cursor\skills\warom-open-workflow\SKILL.md`

这是个人技能，不放进某个业务仓库，也不放进 `skills-cursor`。

`SKILL.md` 不设置 `disable-model-invocation`，这样用户直接说「打开请假流程」「我要发起内部留言」时，agent 会按描述自动使用它。

描述用第三人称，写明两件事：在华荣照明信息平台 `v2_debug_ouyang` 里按用户说法打开发起弹窗；用户提到打开、发起、新建某条流程，或提到该站点的流程定义页时使用。

## 不保存流程名单

`SKILL.md` 和同目录文件里不出现具体流程的名称、代码、主视图对照表。截图里当时有的记录只说明页面长什么样，不写入技能。

每次执行都重新读取流程定义页的当前列表。新增、改名、改代码、禁用之后，下一次打开使用新的结果。

## 列表从哪里来

流程定义页的表格是 `task-form-view`，视图代码为 `WorkflowDefinition`，查询方案属性为 `1`。表格数据来自：

`POST /system/entity-query-solution/task-form-view-query/WorkflowDefinition`

请求体与页面 `loadData` 一致：

- `solution`：该视图当前查询方案的 ID
- `columns`：方案里的字段名
- `order`：方案排序，没有则为空数组
- `pagination`：`start` 从 1 开始，`end` 先取 500。若 `rowCount` 大于已返回行数，按同样条件继续请求剩余区间，直到行数达到 `rowCount`
- `where`：空数组
- `keyword`：空字符串

返回体使用 `rows` 和 `rowCount`。行数据里要能读出名称、代码，以及页面用来判断禁用的 `DisableStatus`。`DisableStatus` 为 `1` 表示已禁用，与该页行操作的判断相同。

查询方案 ID 和列字段不写死。执行时在已登录页面里先取 `WorkflowDefinition` 的查询方案，选中该页 `query-solution="1"` 所对应的方案；字段名对不上时，用返回列里表头为「名称」「代码」「主视图」的字段。

接口的主机前缀使用这个页面已经在用的 API 前缀，从该站点已发出的请求里看，不另猜一台服务器。请求走当前页的登录态。技能文件和回复里不记录口令、请求头或令牌。

若方案 ID 或列字段还无法组成上述请求，就先进入不带 `code` 的流程定义页，从表格已加载的行读取「名称」「代码」和禁用状态。表格声明还有未加载的行时，继续翻页，直到名称匹配结束或行已读完。然后再按下面的规则跳到带 `code` 的地址。

`/workflow/task-form/definition/query` 是定义维护接口，不作为这份名单的来源。

## 怎样匹配用户的话

从用户原话里反复去掉这些说法：请、帮我、帮忙、我要、我想、想要、打开、发起、新建、填写、填一张、一下、这个。

去掉之后如果还以「流程」结尾，并且「流程」前面还有文字，再得到一个去掉「流程」的候选词。原话、去掉客套后的文字、再去掉「流程」的文字，三个都参与匹配。比较时忽略大小写和空格。若三个候选都为空，先问用户要发起哪条流程，不把列表里的全部记录当成命中。

一条未禁用的记录命中，满足任意一条即可：

- 名称与候选词相同，或名称包含候选词
- 候选词包含名称，且名称至少两个字
- 代码与候选词相同；比较前按页面规则去掉前导零
- 主视图与候选词相同

只命中一条未禁用记录：打开它。

命中多条未禁用记录：列出这些记录的名称和代码，请用户选，先不跳转。

没有未禁用命中，但有已禁用命中：说明该名称当前已禁用，不能发起，不跳转。

完全没有命中：列出本次读到的名称，不猜测代码，不跳转。

## 怎样打开

命中后的地址：

`https://test.warom-lighting.com/v2_debug_ouyang/#/workflow/workflow-base/agent?code=` 加上该行当前的代码。

当前浏览器已经在这个站点前缀下的任意 hash 页面时，只改 hash。当前不在这个站点时，打开完整地址。

当前 hash 的 `code` 已经是目标代码，并且发起弹窗已经可见：停止，告诉用户弹窗已打开。

当前 `code` 相同，但弹窗不可见：先进入不带 `code` 的流程定义页，再进入带目标 `code` 的地址，让页面的 `code` 监听重新执行。

打开后确认发起弹窗出现。页面出现「未找到可发起的流程定义」或「打开流程失败」时，把这句原文告诉用户。

不点击行上的「编辑」。不在定义编辑页里保存或修改流程。

## 登录

地址进入 `#/login`，或页面同时出现用户名、密码和登录时，停止操作，请用户在该浏览器里登录。技能不输入密码，不保存密码。

## 完成标准

- 用户在该站点任意已登录页面说「打开请假流程」时，agent 按当时列表里名称含「请假」的那一条代码打开发起弹窗。
- 用户说一个列表中不存在的名称时，agent 列出当前名称，并且地址里的 `code` 不变成猜测值。
- 技能目录中的文件不包含流程名称与代码的固定对照表。
